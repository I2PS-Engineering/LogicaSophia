# Architecture — LogicaSophia

**Built by I2PS Engineering · Engineering Preview v0.7.0**

## Engineering goal

Deliver an original, auditable, model-independent Linux AI application with useful tools and eventually broad autonomous engineering ability. The design distinguishes **inference** (optional models), **control** (I2PS host policy), and **evidence** (observed inputs and real outputs). Neither OpenClaw nor proprietary leaked source is redistributed in this project.

## Current layers

1. **Interface:** PySide6/Qt desktop, organized as Assistant, Create and Results. The historic local browser interface remains an optional secondary entry point, not the desktop product identity. The supplied gold JPEG is used without modifying the source asset.
2. **Unified dispatch:** `workbench.py` performs bounded, deterministic task classification. `plan_instruction` returns an explicit operation and missing requirements without side effects. `execute_plan` requires `confirmed=True`, executes a permitted tool and writes a per-run output/evidence record.
3. **Native analyzer:** `native.py` provides controlled Python AST inspection. The agent protocol and file tools permit reading and text searching within a selected directory. It does not have general code-writing or arbitrary shell authority.
4. **External inference connector:** A localhost OpenAI-compatible adapter is available for deliberate model selection. No third-party foundation model is required at application startup. A model's suggestions are validated by host tools, not trusted as completed work.
5. **Artifact tools:** `artifacts.py` computes statistics and renders actual PNG/PDF engineering charts or user-defined architecture diagrams.
6. **Image adapter:** `images.py` connects to a separately running ComfyUI service and an explicitly installed checkpoint. Optional authentic-logo overlay uses a supplied file and chosen placement; generated images are never simulated when no model is present.
7. **Speech/narration:** `lexia.py` incorporates the approved I2PS voice kit and staged authorization; `speech.py` handles synthesis. Voice weights are separately obtained and hash-checked.
8. **Evidence:** Source SHA-256 hashes, generated-output digests, run status, timing/parameters and audit files are retained. The system labels uncertainty and failed preconditions instead of inventing success.

## Execution paths

**Engineering CSV:** user instruction → plan containing exact CSV path and numeric columns → user confirmation → scoped CSV read → statistics → PNG chart + PDF report → artifact manifest.

**Architecture:** explicit labels and arrows → bounded node/edge graph → user confirmation → PNG/PDF renders → hashes. Components and system relationships not present in input must not be invented.

**Text-to-image:** prompt → required checkpoint/logo checks → user confirmation → local ComfyUI → returned image bytes validated → optional authentic logo overlay → PNG + manifest. No image is generated by the native AST analyzer.

**Lexia narration:** script → known/unknown pronunciation audit → short real voice test → explicit approval → per-slide WAV files + combined WAV, timing JSON, SRT and hashes. Model availability is mandatory for audio generation.

**Native analysis:** goal and authorized workspace → filenames → controlled read/search → deterministic AST analysis where supported → verification → final answer and trace. Unsupported problems should return uncertainty.

## Security and scope

- Localhost-only external adapters unless separately re-engineered and reviewed.
- Tool access is narrower than general host access; paths are scoped and symlink/traversal rules are enforced in the file observation layer.
- Explicit confirmation before the unified dispatcher creates output files; results go outside the input workspace.
- Model prose is not an authorization token, and prompt-injection-resistant behavior is a goal, not a formal guarantee.
- A valid checksum never proves a source-derived conclusion is correct.
- The v0.7.0 package is a research/engineering preview, not a multi-user or publicly exposed inference service.

## Separation from other I2PS infrastructure

LogicaSophia is **standalone**. Cluster orchestration, Atlas Nexus, Orion, Phoenix, Data Core and other infrastructure are **not prerequisites** for the application. Remote execution, distributed inference and failover may be integrated only in later qualified versions.
