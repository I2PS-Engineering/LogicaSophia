# LogicaSophia — Engineering Roadmap

**Built by I2PS Engineering**

LogicaSophia's goal is useful, observable engineering intelligence. The next milestones must add capabilities in a measurable sequence rather than confusing a graphical button with a working model.

## Current baseline — v0.7.0

Model-independent native analysis; bounded task dispatcher; working CSV-to-PNG/PDF and architecture renders; Qt Studio code; image diffusion adapter; approved Lexia speech/narration controls; source/output evidence and I2PS attribution.

## Qualification gates

1. **Qt on Ubuntu:** install declared dependencies; launch actual Assistant/Create/Results UI; capture genuine screenshots; inspect ergonomics and memory consumption.
2. **Lexia:** obtain checksum-verified Kokoro resources; audit a real script; render an approved short voice test; approve and render a slide; verify WAV/timing/SRT.
3. **Image generation:** install a known image checkpoint on appropriate compute; generate a genuine cat-skateboarding sample; overlay the **real** I2PS logo; inspect scale, alignment and source provenance.
4. **Engineering benchmark suite:** test real CSV/architecture workloads, manually validate calculations, measure CPU/RAM/latency and review input/output hashes.
5. **Agent reliability:** add explicit factual assertions, independent tests and uncertainty calibration; measure task success beyond merely returning a file.

## Longer-term development (not yet delivered)

- Modular, more capable reasoning and planning behind I2PS policy boundaries.
- Human-reviewed code modifications, isolated build/test execution, rollbacks and provenance.
- Long-lived retrievable memory with source attribution and deletion controls.
- Broader formats for images, graphics, reports, presentations and narrated video.
- Hardware-aware scheduling and optional remote Linux workers, independent of Atlas infrastructure.
- Investigation of an independently trained foundation model, subject to separate training data, computational budget, evaluation and licensing decisions.

Every new feature should pass **real output tests**, not merely show a mockup or “ready” label.
